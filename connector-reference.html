Back-Office Integration Reference

For partners building on Shopify for small-to-mid merchants. Match a merchant's back-office system — ERP, inventory (IMS), or accounting — to the right Shopify integration path, know the limits before you scope, and find the vendor who actually supports it. Scope confidently on your own.

Scope: centered on SMB & Mid-Market. Enterprise systems (SAP S/4 & ECC, D365 F&O, JD Edwards, Oracle EBS, Manhattan) are shown dimmed and tagged ENT — they're typically GSI-led and beyond a scaled build. Filter to SMB/Mid-Market to hide them.

Unofficial field reference — not official Shopify documentation. Always verify against the Shopify Help Center and Partner docs before scoping. Vendor mentions are examples, not endorsements. Spot something off or out of date? Open an issue.  ·  Last updated: June 2026

Mental model

Shopify is the storefront / sales-channel & order layer — usually not the system of record. The ERP/IMS stays the source of truth for pricing, inventory & finance. Sync is async (webhooks + API). There is no live ERP call at checkout on standard plans — sync data into Shopify ahead of time.

Pick your integration path

Native/config first — then work down this order, custom last:

  1. 1P / certified connector — least effort, vendor-supported
  2. Certified middleware (iPaaS) — Celigo, Jitterbit, Pipe17, VL Omni
  3. App-store connector — the SMB default (QuickBooks, Cin7, Katana…)
  4. Custom build — only when nothing above fits

POS reality

Nothing integrates directly to POS without a POS UI extension. POS orders flow through Shopify admin, and the back-office system integrates to admin. Purchase orders and receiving are native in admin and POS now; what's still limited is a programmatic PO API to push ERP-generated POs in automatically — verify current API coverage before scoping that.

The two keys you'll need

Use order.id as the cross-system match key (not the order name or confirmation number). For payments reconciliation, the gateway key is now payment_id — wire the ERP to that, not legacy gateway transaction IDs.

Set these expectations with the merchant before you scope

How to use this: these deals often don't get formal pre-sales support from Shopify, so this guide is meant to give partners enough context to scope independently. Find the merchant's system, pick the path, read the limits, contact the listed vendor/app. Start at the App Store listing or the vendor's site; for custom work, the integration tier tells you roughly what you're signing up for.

Segment legend: SMB = self-serve, app/connector-driven · Mid-Market = larger catalogs/volume, ERP migration often best deferred until after launch · Enterprise = GSI-led projects, usually out of scope here.
